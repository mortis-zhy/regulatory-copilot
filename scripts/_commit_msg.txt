feat(泛化)：页数与源文档清单从语料派生 —— 下载文件名原来还会讲 GB 4785

盘点「换一套标准要改多少东西」时发现：交付件里有**三处写死的页数**。

| 位置 | 原来写着 |
|---|---|
| 第 2 章「三份法规概况」表 | 103 / 81 / 147（整行写死） |
| 执行摘要「5. 对照范围」 | A 草案 103 页 / B 现行 81 页 / C UN R48-09 147 页 |
| **源文档清单** `sourceDocuments` | `{ label:"A", name:"GB 4785 草案 V4.3.5（103 页）" }` 等三行 |

第三处最要紧：**下载文件名是从它派生的**（server/reports/reportFileName.ts）。
上一轮把「文件名派生」做对了 —— 但它的**输入**还是写死的，
所以「换了标准，下载下来的文件名还在讲 GB 4785」这个毛病**根本没治好**。
症状不报错：文件名长得像模像样，只是讲的还是上一套标准。

页数是**语料的事实**，不是声明 —— 它该被数出来，不是被写下来。
换一套标准、或源 PDF 换了版，写死的页数全是错的，而报告照出。

改法：
- `VERSION_META` 扩成一张表，装下「关于这个标准报告需要知道的一切」：
  label / desc / **doc**（文档显示名）/ **std**（标准号）/ **status**（状态）；
- 页数从语料数：`pageCountsOf()` —— ①源 PDF 语料的页数（权威）
  ②MinerU 分页文本的 `[第N页]` 标记（实测与源 PDF 一致：A 103 / B 81 / C 147）；
  数不出来就**不写页数**，不拿别的数凑（「宁可空着，不可错着」）；
- 三处全部改为派生。

**输出零变化**：重建后 `reports/last-report.json` 与改前**逐字相同**
（仅 generatedAt 不同），渲出的 PDF 与已交付的 ㉝ **逐页相同**
（258 页，只差封面那一行编制日期）。这正是该有的结果 ——
把写死的改成派生的，不该改变当下的交付件。

新增闸门「the report's page counts come from the corpus, not from literals」：
①源码里不许再出现写死的页数；②**功能** —— 交付件里写的页数必须等于语料数出来的页数。
已反向测试：把交付件的页数改成 999 → 闸门红。

122/122 闸门绿。
