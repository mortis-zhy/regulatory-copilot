## 1. 输入侧：文件怎么进来

| 环节 | 实现 | 关键事实 |
|---|---|---|
| 上传 | `server/_core/agentRoutes.ts` → `POST /api/agent/documents` | 文件按**内容 sha256 前 16 位**命名：`uploaded-docs/<sha16>.pdf` ✓（同一份文件永远同一个名 ✓ ⇒ 不会被后一份顶掉 ✓） |
| 版本识别 | `server/_core/versionAssignment.ts` + `shared/versionMeta` | 按**内容**认（不是文件名 ✓）；认不出 ⇒ 界面明说「认不出」✓（不让用户等到出报告才发现矩阵是空的 ✗） |
| 冲突检测 | 同上 | 两份被认成同一版 ⇒ 顶部**红色横幅** ✓（角色认错 ⇒ **变化方向会反** ✓） |
| 人工改判 | 界面下拉框 | **机器的判断可以被改** ✓，改过的优先 ✓ |
| 案例包判定 | `data/standard-pack.json` | 不适用 ⇒ **明确拒绝** ✗（拿别的标准的数据糊弄过去比「查不到」坏一个数量级 ✓） |
| 任务隔离 | `server/_core/taskContext.ts` | 每个浏览器会话一个任务 id（`X-Task-Id`）✓；报告落 `reports/tasks/<id>/last-report.json` ✓（两个任务并行不互相覆盖 ✓） |

## 2. 解析侧：PDF → 结构化语料

| 解析器 | 何时用 | 产物落哪 |
|---|---|---|
| **native** | 前端 pdfjs / 服务端 MuPDF WASM | `server/ingestion/pdfExtract.ts` |
| **mineru** | `PYTHON_SERVICE_URL` 配了 ⇒ 走 python sidecar（`server/_core/sidecarClient.ts`，端口 **8300** ✓） | 同上 |
| **rag-anything** | 外部服务配了 | 同上 |

三条路都产出**同一形状**（`server/ingestion/pipeline.ts` 的 `ParsedBlock[]` ✓）：
`heading / paragraph / table / figure / footnote / appendix` + 页码 + bbox + 置信度 ✓。

**抽图是另一条线** ✓：`scripts/extract_figures.py` 从**源 PDF** 抽位图到
`dist/figures/<源文件 sha8>/p<页>_<序>.png`（200 dpi ✓）。
> 为什么不用 MinerU 的 base64 ✓：base64 在 markdown 里没有页锚点 ✓，
> 与 `figures[]` 的页码**对不上** ✓ ⇒ 硬配就是「图和它的题注对不上」✗ ⇒ **宁可空着，不可错着** ✓。

**语料主产物**：`dist/mineru-v4-data.json`（11.6 MB ✓）—— 每版一份，带 `sourceSha256` ✓
（**上游指纹** ✓：源 PDF 一换，下游全部作废 ✓）。

## 4. 报告层：`reportV6.ts`

```
reportV6.ts
 ├─ 参数矩阵（319 行 × 3 版 = 957 槽位）
 │    ← data/parameter-specs.json + dist/facts.json
 ├─ 差值判定（哪一格算变化、为什么）
 │    ← data/diff-corrections.json + facts.json
 ├─ 定性义务（412 条）→ 附录 E.5.1
 │    ← data/qualitative-ledger.json + qualitative-obligations.json
 ├─ 主题对照（逐条核验）→ 附录 C
 │    ← facts.json（topicColumns ✓）
 ├─ 附录 B
 │    ├ B.2 图片清单（索引）
 │    ├ B.2.1 图版（**102 张源 PDF 原图** ✓）
 │    └ **B.5 跨版素材对比**（图 / 表 / 公式 ✓）
 │         ← multimodal.ts 的 buildInventory / diffVersions
 │              图：pHash 配对 + OCR 数字 + 人工标注
 │              表：题注/可读表头配对 + 单元格级 diff（逐格判串行 ✓）
 │              公式：归一化相同 + 符号表（定义/单位/页码 ✓）
 └─ 正文散文
      ← data/report-prose.json（**散文在数据里，不在代码里** ✓）
```

**B.5 的三条硬线**（报告里逐条写着 ✓，用例钉住 ✓）：
1. **近似 ≠ 一致**（pHash 对「图上改一个数字」几乎不动 ✓）；
2. **配不上就说配不上**（「本版未找到近似图」≠「那一版删了这张图」✓）；
3. **串行/乱码不比**（抽取坏了 ⇒ 比出来的是**假差异** ✗）。

## 6. 在线问答层（不进交付件 ✓）

```
浏览器输入
  → POST /api/agent/chat/agent
  → server/reports/agentLoop.ts（多轮 tool-calling ✓）
      → server/reports/agentTools.ts 的 **11 个只读工具**
      → 结果塞回对话，继续下一轮
      → **连续两轮什么都没查着 ⇒ 强制收口** ✓（不许编 ✓）
  → 回答带证据：页码 + 原文 + evidenceScope（任务 id / 案例包 / 源文件 / 用到哪几版）
```

| `list_requirement_gaps` | 没进矩阵的要求 | `data/requirement-ledger.json` ✓ |
| `get_topic_excerpts` | 主题的三版原文 | `dist/facts.json` ✓ |
| **`compare_figures`** | 两版的**图**差在哪 | `figure-hashes` + `figure-ocr` + `figure-limits` ✓ |

**任务隔离贯穿问答层** ✓：当前任务没有的那一版 ⇒ 工具**明确拒绝**（`version_not_in_task`）✓

## 11. 三条贯穿全链路的红线

1. **宁可空着，不可错着** ✓ —— 抽不到就写「未找到」✓；串行不比 ✓；没标注不等于没有 ✓。
2. **每个事实都要能回源** ✓ —— 取值带条款号 + 页码 ✓；引文 517 条**逐条回核** ✓。
3. **数字不许手写** ✓ —— 闸门数、页数、图数、泛化率、工具数**全部从机器读** ✓
   （`dist/verify-summary.json` ✓ · `reports/page-count.json` ✓ · `dist/agentTools.js` ✓）。
   ⇒ 文档过期 ⇒ **闸门会红** ✓ —— 读者不会照着旧数做决定 ✓。
