## 3. 过程中发现并修掉的一个**真缺陷**

**症状**：同一份 R148，**喂 11–17 页** ⇒ 切出 **72** 条条款、条款号全对 ✓；
**喂全本 50 页** ⇒ 只切出 **2** 条，条款号还是垃圾（`30.9.2021`、`400.1`）✗ ⇒
候选里 **0 条带锚点** ✗（`35` 条候选全是 `candidate-<hash>` ✗）。

**根因**：条款号是**连续链条** ✓（`same_chapter` ✓）—— 好处是不把正文里的交叉引用
（「按 4.11 要求」）当成条款开头 ✓。但链条的**起点**要是认错了，后面**全被带偏** ✓ ⇒
封面/前言里一个像条款号的数字（`30.9.2021` ✓）把链条锚在了它上面 ⇒
真正的第 4 章被当成「章号变小」⇒ **一条都认不出** ✗。

**修法**（`scripts/clause_split.py`）：
1. **章标题 = 链条重开点** ✓ —— 英文本的章标题是 `4.` + `GENERAL TECHNICAL REQUIREMENTS`
   （**PDF 把号和标题拆成两行** ✓）⇒ 见到它就重开链条 ✓；
2. 判据**三条都要**：章号是 **1–20 的裸号带点** ✓（`4.` ✓）· 后面那条**全大写** ✓ ·
   章号 ≤ 20 ✓（附录编号 400/500 不是条款 ✓）；
3. **只丢章号 > 20 的** ✓（封面日期 ✗ / 附录编号 ✗），**章号合理的留着** ✓
   （`3.9` 是第 3 章的真条款 ✓ —— 一刀全丢会把真条款删掉 ✗）。

**修完的实测**：

| | 修前 | 修后 |
|---|---|---|
| R148 全本条款 | **2**（垃圾号）✗ | **150** ✓（4.x 74 条 ✓） |
| R148 全本候选 | 35（**0** 带锚点）✗ | **159**（**140** 带锚点）✓ |
| **GB 三版条款数** | 609 / 501 / 951 ✓ | **609 / 501 / 951**（**一字未变** ✓） |

⇒ 中文本**零影响** ✓ —— 因为全大写判据对中文章标题（「4 一般要求」）**不成立** ✓。

**两个用例把它钉住** ✓（`scripts/test_clause_split.py`，4 条 ✓），
并且**进了闸门** ✓（`the python test suites pass` ✓ ——
之前 Python 用例只在人手动跑时才跑 ✗，这就是这个缺陷**没人发现**的原因 ✗）。

## 5. 仍然**没有**验证的（诚实清单 ✓）

1. **候选 ≠ 要求全集** ✓ —— 工具自己写着 `requirementsComplete=false` ✓；
   14 处未触发候选 ✓、102 个未支持对象 ✓（图表/公式/图引用 ✓）都**留了台账** ✓。
2. **语义没核** ✓ —— `semanticallyVerified=false` ✓；候选是不是**要求**（而不是说明/交叉引用）✓ 要人判 ✓。
3. **条件继承** ✗ —— 父级上下文**带出来了** ✓（`context` ✓），但「父级条件要不要算进子条款的要求」**机器没判** ✓。
4. **图表语义** ✗ —— 9 处表格上下文 / 3 处公式上下文 / 2 处图引用**只登记不解析** ✓。
5. **换一整套标准后的整条链路** ✗ —— 本次只到「**候选清单**」✓；
   从候选到「可发布的对比报告」这一段**还没在真法规上跑过** ✗。
