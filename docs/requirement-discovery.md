# 无参数清单的离线要求候选发现

## 做什么，不做什么

`discover_requirements.py` 从显式输入的 PDF 中扫描要求**线索**，无需先提供参数表、章节映射或案例答案。不使用模型、网络、OCR 或现有报告。引擎复用 `clause_split.clause_starts()` 和 `limit_scan.scan_limits()/scan_decimals()` 的纯函数，不调用现有语料自动选择入口。

输出是**研究候选和处理范围台账**，不是已核法规要求、参数矩阵或可交付对比报告。它不做跨版本语义对齐，也不改变现有报告的案例包拒绝保护。

候选的 `context` 保留先前可定位父条款的原文证据，状态为 `unverified_context`，供人核对条件和义务。父级出现义务词时，子条款可因 `parent_requirement_context` 进入待核候选；这不等于已解析继承关系。跨未选中页面断档不沿用父上下文。整数章标题采用保守启发式识别，并非通用 PDF 章节解析器。

- 候选有原文 ≠ 对象、适用条件、符号、单位归属正确。
- 没有候选 ≠ 没有规定；必须检查没有产生候选的原文。
- 处理台账闭合 ≠ 要求完整；机器可能根本没有识别出某项要求。
- 最后只剩几项待核 ≠ 人工成本只有几格；准备、发现漏项、修正和独立评测分别记账。

## 使用

环境：Python 3.10+、PyMuPDF（本轮验证版本记录在产物 `source.extraction.version`）。无需 `.env` 或模型密钥。

在内层仓库根目录运行：

```sh
python -B scripts/discover_requirements.py --pdf /path/to/source.pdf --version revision-X --pages 4-8 --out tmp/discovery/revision-X-run1
```

- `--pdf`：明确传入的本地 PDF。直接读这些字节并计算 SHA-256；不按文件名猜法规身份。
- `--version`：非空的调用者标签，**未经内容识别**。可用任意版本名，不限于现有案例的版本键。
- `--pages`：从 1 开始的 PDF **物理页**，支持 `4-8` 或 `4,6-8`；省略时扫描全部。无效、空或越界范围报错，不静默裁剪。
- `--out`：必须是**尚不存在**的目录，连已存在的空目录也拒绝。两份产物均用排他创建模式写入；没有覆盖开关。重跑请另取目录名。
- 禁止输出到当前项目的 `data/`、`dist/`、`reports/`、`delivery/`、`uploaded-docs/`、抽取缓存、OCR 工作目录或 `.git/`。路径先解析，不能用 `..` 绕过。

退出码：

| 码 | 含义 | 产物 |
|---|---|---|
| `0` | `complete`：选中页的线索扫描完成，未遇到已登记的未解析内容 | 有；**不代表语义通过或无漏项** |
| `3` | `partial`：有未解析的图形、表格、公式线索、无文本页，或局部抽取异常 | 有；必须看台账，不能当作完整成功 |
| `1` | `failed` 或输入／输出错误 | 页级失败能形成台账时有产物；输入无效或输出冲突时不新建结果 |
| `2` | argparse 命令行用法错误 | 无 |

纯文字页即使没有触发任何候选，也可返回 `complete`，其含义仅是扫描程序执行完毕。未选中页始终是 `not_processed`，不计入本次已扫描范围。

## 输出格式

同一结果生成 `discovery.json` 和便于逐页查看的 `review.md`。

| 字段 | 含义 |
|---|---|
| `source` | 文件名、PDF SHA-256、调用者标签、总页数、选中页、抽取引擎版本与文本模式 |
| `generator` | 生成器名称及执行所需脚本的源码 SHA-256 |
| `claims` | `requirementsComplete=false`、`semanticallyVerified=false`，不可升级 |
| `run` | 执行状态，非语义验收状态 |
| `pages` | **所有物理页**的处理去向，包含范围外的页 |
| `fragments` | 选中页所有非空文本行（页、块、行、块边界框），以及图形／表格布局／异常线索 |
| `candidates` | 原文、触发原因、条款候选、量值词法线索、逐行证据引用；稳定 ID 绑定源指纹、版本标签和片段位置 |
| `ledger` | 每个片段恰好一条处置，回指相关候选 |
| `limitations` | 文本中的表格、图示引用、公式线索及其位置；图形对象还登记在 `fragments/ledger` 中 |
| `summary` | 从产物实际记录重算的计数，不是法规要求总数、准确率或人工工时 |

片段处置：`scanned_with_candidate`（有候选）、`scanned_without_candidate`（未识别候选）、`unsupported`（登记但未解析）、`parse_failed`（抽取异常）。页面状态为 `scanned`／`unsupported`／`parse_failed`／`not_processed`；文字中的表格或公式线索也会使整次执行为 `partial`。

候选 `evidenceStatus=located` 只表示引文与该页的**本次文本快照**一致。`semantics.status` 始终为 `unverified`；`subject/conditions/comparator` 留空并解释原因，不从词法命中猜语义。

校验检查页清点、页面状态与片段一致、候选引用的页码／原文／源绑定 ID、片段处置分区、汇总和执行状态。它不是 PDF 签名系统，也不防止攻击者同时重写整份快照；复核源件时仍需对 PDF 指纹及源页原文。

## 已知边界

- 中文及英文规范词和量值只触发线索，不能穷尽自然语言要求。单位词典、数值写法和条款起点识别仍是启发式；新单位、负数、分档、编号跳转等必须回原文检查，不能直接采纳 `quantities` 为规格。
- 一条候选可能合并同条款内多个义务，或包含页眉、脚注、交叉引用。条款是 `candidate_anchor`，并未证实正文归属；非连续页不会拼为一个条款。
- 文本取 PDF 内容流原始块序（`sort=False`），没有多栏阅读顺序重建。保留原始文本和块坐标，不冒充视觉顺序。
- 表格检测只登记布局及行列数；裸数字留在正文快照，不猜配单元格、表头和适用条件。未检测到表格也不能证明没有表格。
- 图像保留显示位置、尺寸；矢量对象只记路径数，**路径数不等于图数**。不解释图中限值、不做 OCR；扫描页和无文本页必须留在台账里。
- 部分页选择是物理范围，不是语义章节选择；某章结束页可能同时有下一章内容，需在验收范围中注明，不能悄悄删掉。

## 验证与真实法规实测

词法线索也包含“视同批准”及条款/附录交叉引用。引用本身可形成待核候选，但不会自动解析被引内容或继承父条款义务。已知父子条款和阅读顺序问题见 [R148 开发侧清点](requirement-discovery-r148-audit.md)。

```sh
python -B scripts/test_requirement_discovery.py
node _test_swap_standard.mjs
npm run verify
```

新增 Python 测试由已有 `_test_swap_standard.mjs` 调用，保留原有全部映射断言，不人为增加顶层闸门数。顶层结果只读 `dist/verify-summary.json`。

合成 PDF 已知答案用于验证实现与失败记账，**不是法规泛化成绩**。真实输入试跑及未完成事项见 [R148 实测记录](requirement-discovery-r148-smoke.md)。

真正验收新法规还需要：

1. 固定源文件身份、版本、指纹与一个完整章节；系统运行前不提供参数答案。
2. 先产出候选，再以源章节独立列出要求、量值、单位、符号、条件、例外和证据，找误提也找漏提。
3. 对表格和图中要求建立独立清点；未解析不能从验收分母消失。
4. 机器辅助开发核对与独立人工验收分开。没有全章逐项独立答案，就不计算召回率或语义正确率。
5. 分别记录接入准备、运行后复核、修正返工、独立评测的实际操作与计时；不知道的工时写未记录，不能用候选数冒充。
6. 对照既有案例 JSON、报告和交付 PDF 的 SHA-256，确认新入口没有覆写旧案例。
