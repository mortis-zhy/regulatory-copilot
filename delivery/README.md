# delivery/ —— 交付材料

代码在仓库根，**交付给客户的东西在这里**。整个项目一个仓库，克隆下来既能跑管线，
也能直接看到要交出去的 PDF。

> **为什么单独一个目录**：交付材料和代码的寿命不一样。
> 代码天天改，交付件是**定版**的 —— 改坏了要能立刻发现「交出去的那份没被动过」。
> 混在仓库根里，两件事会互相污染。

## 二、「需求」在哪 —— 这个项目没有 PRD 文件

这个项目是**从客户差评倒推**做的，从一开始就没有一份叫 PRD 的文档。
需求分散在四个地方，各管一段：

| 层次 | 文件 | 管什么 |
|---|---|---|
| 需求源头 | `PDF对比/feedback.md` | 客户原话：「数值有提取错误或空缺」「只有罗列，无对比」 |
| 逐条需求 | `PDF对比/分析报告/📋_客户差评逐条对照_验收版.md` | 每条抱怨 → 我们改了什么 → 当场怎么验 |
| **对照口径** | `../data/requirement-scope.json` | **哪些进对照、哪些不进，每条带可核对的理由** |
| 要求台账 | `../data/requirement-ledger.json` | 448 条要求逐条处置：已覆盖 286 / 附录列出 65 / 不适用 45 / **缺口 0 / 弱覆盖 0** |

`requirement-scope.json` 是最接近 PRD 的那份 —— 它定义的**对照口径**是整个报告的边界：
「灯具/装置的安装与光学参数」进，「型式批准程序、标志、生产一致性、过渡安排」不进
（法规程序不是产品设计输入），每一条不进的都写了理由，理由要能让人核对。

## 三、三份源 PDF —— 取值的原始依据

`PDF对比/源文件_A|B|C_*.pdf` 是**三份法规原文**：

| | 文件 | 版本 |
|---|---|---|
| **A** | `源文件_A_GB4785草案V4.3.5_103页.pdf` | GB 4785 草案 V4.3.5 |
| **B** | `源文件_B_GB4785-2019_81页.pdf` | GB 4785-2019 |
| **C** | `源文件_C_UN-R48-09_147页.pdf` | UN R48-09 |

**抽不到值时要靠它们重来**，所以一份都不能删。

> 仓库里它们有**两条路径**：`uploaded-docs/<内容哈希>.pdf`（管线读这里，路径写死在 8 处代码里）
> 和这里的可读名副本。**字节完全相同**（sha256 一致），git 只存一份 blob，零额外体积。
> 详见 `../uploaded-docs/README.md`。

## 五、重新生成

```bash
cd <仓库根>
npm install
npm run build              # dist/*.js 是构建产物，不入库
npm run verify             # 交付闸门，红了不许交付
node rebuild_report.mjs    # 重建报告数据
node render_to_pdfdir.mjs  # 出交付 PDF → delivery/PDF对比/
node scripts/render_briefing.mjs   # 出讲稿 → delivery/宣讲件/
```

出稿前**必须**先跑 `verify` —— 讲稿里那句「N 项闸门」是从 `dist/verify-summary.json`
读的，读不到就拒绝出稿。

> **新克隆的同事能跑到第几步**：`npm install && npm run build` 之后就能跑完整的
> `npm run verify` —— 闸门要用的抽取语料（`dist/mineru-v4-data.json`、
> `dist/verified-comparison.json`、`dist/facts.json`、`dist/extract-cache/v3-*.json`）
> **在库里**，不用重新生成。
>
> 再往后（重新抽取、重新调 LLM 跑差值）需要 `.mineru-models/`（853 MB，不入库）
> 和 API key —— 那是在**原作者那台机器**上做的事，新克隆的同事不必重复。

## 六、历史在哪儿

`delivery/` 里只有**当前**交付材料。交付材料的**形成过程**（外层工作台的
逐版本脚本、`latex_output/`、历次审计脚本）不在主分支上，在同一个仓库的
归档分支：

```
archive/workbench-2026-10-28
```

那是**同一个仓库**的另一个分支，`git log` 直接能看，不用另开仓库。

> ⚠️ 归档分支里的 `verify_claims.py` 等脚本与仓库根的**同名但是旧副本**。
> **闸门用的是仓库根那一版**，别拿归档分支的脚本跑。
