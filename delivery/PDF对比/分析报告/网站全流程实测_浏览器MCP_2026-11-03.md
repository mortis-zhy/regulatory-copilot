# 网站全流程实测（Chrome DevTools MCP）

**日期**：2026-11-03
**环境**：真实 Chrome 156.0.8078.76（CDP 9222）· Node 22 · 本机 8GB 显存卡
**被测对象**：`http://localhost:3004`（`npm run dev`，源码模式）

## 〇、为什么用浏览器测

前面的验收都是**命令行**：跑 `npm run verify`、跑 `rebuild_report.mjs`、跑 `render_to_pdfdir.mjs`。
那些测的是**产物**，不是**产品**。

网站那一侧此前只验到「跑得起来」。这次把**真实用户路径**走了一遍：

> 打开网站 → 传三份源 PDF → 点「生成完整报告」→「MinerU 高精度报告」→
> 点「下载 PDF」→ 把下载下来的文件与交付件逐页比。

**这一趟挖出十个真问题**（第一轮八个，第二轮两个），每一个都是命令行测不到的 ——
而且其中九个在**网站这个产品**上，命令行验收（跑 verify / rebuild / render）
**结构上就测不到**。

> 最后一个（问题 7）是**最阴的一个**：
> 弹窗里那个最顺手的「下载 PDF」按钮，
> **出的是一份缺 8 页的报告** —— 页数变了，其余一模一样，
> 页面上看不出任何区别。

## 二、挖出的八个真问题（都已修）

### 问题 1：网页文案里的数字全是旧的 —— 而且把 MinerU 路径说成了 LLM 路径

页面原文：

> 完整对比报告（**20+ 页 PDF**）
> Regex 提取 + 动态 **13 章** + 逐章流式生成 + 专业排版，约 **15-20 分钟**

实际：**258 页 · 14 章 · 约 2 分钟**，而且 **MinerU 那条路根本不走 LLM**（是确定性渲染）。

文案错到什么程度：它描述的是「快速草稿」那条路，却挂在「生成完整报告」的入口上。
**读者按这句话预留了 15–20 分钟，然后被告知只要 2 分钟** —— 他会以为哪里出了问题。

**修**：文案按两条路分别说清楚，并且**不手写交付件的尺寸**。
新增闸门「the web UI does not claim a report size it cannot know」：
只查 **JSX 文本**（`>…<` 之间），客户需求简报里的「至少 20 页」是**要求**不是描述，放过。

### 问题 2：下载文件名写死了 GB 4785 —— 换标准后文件名会骗人

两处写死：

```ts
a.download = "GB 4785 多版本横向对比研究报告.pdf";     // ReportBuilder
link.download = "GB4785_多版本横向对比研究报告.pdf";     // Home.tsx
```

**换一套新标准，网站下载下来的 PDF 名字里还写着 GB 4785。**
文件名是交付件的一部分（收件人先看名字），而它会骗人。

**修**：文件名**从报告的源文档清单派生**（`server/reports/reportFileName.ts`）：

```
"GB 4785 草案 V4.3.5（103 页）" / "GB 4785-2019（81 页）" / "UN R48-09（147 页）"
→ GB4785草案V4.3.5-GB4785-2019-UNR48-09_多版本横向对比研究报告.pdf
```

换标准时自动跟着变：`UNR149-GB24599_多版本横向对比研究报告.pdf`。

**为什么放在服务端**：两条下载路里，只有一条客户端手里有报告对象；
另一条是**服务端**读 `reports/last-report.json` 自己渲染的 ——
在客户端算就得写死标准名。**服务端一处派生，两条路都准。**

> 落地时踩了两个坑，都记在代码注释里：
> ① Node 的 HTTP 层**拒绝非 ASCII 的 header 值** ——
>    直接塞 UTF-8 会得到 `Invalid character in header content`（500），
>    所以自定义头走**百分号编码**；
> ② 去掉「（103 页）」的正则**不能用 `\b`** ——
>    JS 的 `\w` 只含 [A-Za-z0-9_]，「页」不是词字符，`\b页\b` 两边都没有边界，匹配不上。

### 问题 3（最严重）：服务端把文件写到了**管线读不到的地方**

这是本轮最值钱的发现，而且**没有任何报错**。

服务端各处写的是：

```ts
path.resolve(import.meta.dirname, "../reports")          // → server/reports/
path.resolve(import.meta.dirname, "../uploaded-docs")    // → server/uploaded-docs/
```

那**只对打包后的布局成立**（`dist/index.mjs` → `dist/../reports` = 仓库的 `reports/`）。
**开发模式跑的是源码**（`server/_core/index.ts`），`import.meta.dirname` 是 `server/_core/`，
于是 `../reports` 落到 `server/reports/` —— 一个**没人读、没人看**的目录。

后果两条：

| 症状 | 后果 |
|---|---|
| 网站上传的文件写进 `server/uploaded-docs/`，而**回源复核层读的是仓库根的 `uploaded-docs/`** | **网站上传的新标准，管线根本看不见** —— 认不出它是哪一版、复核不了它的取值。**泛化断在第一步。** |
| 网站把报告写进 `server/reports/last-report.json`，而 CLI 与全部闸门读的是**仓库根的 `reports/last-report.json`** | **两份真相来源** —— 这个项目治过好几次的病，又长出来了 |

启动日志其实早就在提示了：

```
[reports] no last-report.json yet — generate one before using /report/last or /report/trust
```

（仓库里明明有 `reports/last-report.json`。）这条日志当时被当成了「还没生成过报告」，
没人往「路径找错了」上想。

**修**：新增 `server/_core/projectRoot.ts` —— **唯一**的项目根解析器
（向上找 `data/parameter-specs.json`，源码布局与打包布局都成立），
服务端所有路径都走它。

新增闸门「the server resolves project paths through one canonical root」：
① **功能** —— 服务端解析出来的路径必须就是仓库根的那两个；
② **源码** —— `server/_core` 下不许再有 `../reports` / `../uploaded-docs` 这种相对写法。

### 问题 4（顺带查出来的）：**快速草稿会覆盖已核验的交付件**

两条管线（MinerU 高精度 / 快速草稿）写**同一个** `reports/last-report.json`。
同事跑一次快速草稿，**交付件就被覆盖了**。

`/report/last` 早就有 `?prefer=mineru` 的护栏（能挡住「读」），
但 **PDF 导出端点没有** ——
于是同事跑一次草稿，点「下载 PDF」拿到的就是**未经回源复核的 LLM 草稿**，
而界面上它长得跟交付件一模一样。
更糟的是：护栏挡得住「读」，**挡不住「覆盖」** ——
已核验的那份从此没了，只能重跑一次 MinerU 才能拿回来。

**修**：
① 两条管线**各写各的文件** ——
   `reports/last-report.json`（已核验）与 `reports/last-report.llm-sse.json`（草稿），
   已核验的那份**永远在**；
② PDF 导出端点**先判 generator 再渲染**，不是就 409 拒绝
   （`?prefer=llm-sse` 可显式接受草稿）；
③ 客户端把服务端的拒绝理由**原样显示**，不许用一句笼统的话盖掉。

> 那是这个项目最贵的一类错：**安静地给出一份未经核验的东西。**

### 问题 5：**快速草稿能冒用交付件的文件名下载下来**

上一轮给 `/report/pdf` 加了 generator 护栏。这一轮发现**还有一条路没护**：

| 导出路径 | 报告从哪来 | 护栏 |
|---|---|---|
| 工具栏「PDF」按钮 | 服务端读 `reports/last-report.json` | ✅ generator 不符 → 409 |
| **弹窗里的「下载 PDF」** | **客户端把报告对象原样 POST 给 `/report/render`** | ❌ **没有** |

更糟的是**客户端把 `generator` 字段丢了**：
`/generate/mineru` 的响应里没有它，`report_complete` 事件里也没有它，
于是服务端**无从知道**这份报告出自哪条管线。

后果：**「快速草稿（未经核验）」下载下来，文件名与交付件逐字相同**
（`GB4785草案V4.3.5-GB4785-2019-UNR48-09_多版本横向对比研究报告.pdf`），
PDF 内部也长得一模一样 —— **页脚、封面、版式，没有一处能看出它没回过源**。
转发给客户时，没有任何地方会提醒。

那是这个项目最贵的一类错：**安静地给出一份未经核验的东西**，
而且这次连文件名都不再提示。

**修**：标记**一路带到渲染那一步** ——
① 服务端两条管线的响应都带 `generator`；
② 客户端把它留在报告对象里；
③ `reportFileName.ts` 按标记派生：**不是 `mineru` 的，文件名里加
   「（快速草稿·未经回源复核）」**；
④ `/report/render` 再把**封面标题**也打上同一个标 ——
   **文件名会转发掉，封面不会**；
⑤ **没有 generator 标记的也算草稿** —— 证明不了它出自已核验管线，
   就不能让它冒充交付件（与 `/report/pdf` 的护栏同口径）。

实测（浏览器里跑真实下载）：

| generator | 下载文件名 | 封面 |
|---|---|---|
| `mineru` | `…_多版本横向对比研究报告.pdf` | 无标记 |
| `llm-sse` | `…_多版本横向对比研究报告（快速草稿·未经回源复核）.pdf` | **带标记** |
| 缺失 | 同草稿 | 带标记 |

新增闸门「a draft can never wear the deliverable's name」
（把上面三种情况都钉住）。**反向测试**：把 `isUnverifiedDraft` 改成恒假 → 闸门红。

### 问题 6：面板抬头把 **MinerU 交付件**说成「模型逐章流式生成」

弹窗抬头（`ReportBuilder.tsx`）只有一句：

> Regex 提取 + 动态大纲 + **逐章流式生成** + 专业 PDF

那句话**描述的是快速草稿**，却挂在「完整对比报告生成」这个抬头下 ——
MinerU 那条路是**确定性渲染**，一个字都不由模型编。

两种都骗人：
把交付件说成流式生成，是**把核验过的东西说成没核验**；
把草稿说成核验过的，是反过来。

**修**：抬头**按管线分支** ——
MinerU 那支说「MinerU 多模态提取 + 逐格回源复核 + 专业 PDF」，
草稿那支才说「逐章流式生成（未经核验）」。

新增闸门「the report panel does not call the verified path stream-generated」：
**同一行**里提到「逐章流式生成」就必须带「未经核验」标记。

> 判据的坑：先按「邻近 200 字」判过，**没抓到** ——
> 抬头那个三目表达式里 MinerU 支与草稿支**只隔两行**，
> MinerU 支的「流式生成」会借着旁边草稿支的「未经核验」蒙混过关。
> **同一行**才是「这一句自报家门」的真实含义。

### 问题 7（最阴）：弹窗里的「下载 PDF」出的是**缺 8 页**的报告

这一条是**第二轮**（改了前六条之后）才暴露的，而且**前一轮的浏览器测试没抓到**。

#### 怎么发现的

把历次从浏览器下载下来的 PDF 按时间排开看：

```
4,584,892 字节  258 页   ← 工具栏「PDF」按钮（服务端读盘渲染）
4,584,893 字节  258 页
4,521,882 字节  250 页   ← 弹窗「下载 PDF」按钮（客户端把报告 POST 上来）
4,521,883 字节  250 页
4,521,884 字节  250 页
```

**两条下载路出来的不是同一份东西。**
250 页那版少了 8 页 —— 少的是第 12 章前面的
「MASTER PARAMETER INDEX」（317 行的参数主索引）。

#### 根因：客户端**挑字段**建报告对象

```tsx
setReport({
  outline: data.outline!,
  chapters: data.chapters ?? [],
  appendices: data.appendices ?? [],
  sourceDocuments: (data as any).sourceDocuments ?? [],
  generatedAt: (data as any).generatedAt ?? "",
});
```

服务端返回的 `parameterMatrix`（317 行）和 `parameterMatrixStats` **被丢掉了**。
而渲染器正是从它建主索引的：

```ts
renderMasterParams(extractMasterParams(chapters, report.parameterMatrix))
```

没有这个字段，渲染器会**退而从章节 markdown 里刮** ——
刮出来的是另一个东西，行数从 317 掉到 41。

**为什么页面上看不出来**：章节、附录、结论全都一样，
只是主索引少了一大截。客户拿到的是一份「看着完整、其实少 8 页索引」的报告。

#### 修

**整个响应原样带过去**，不要挑字段：

```tsx
setReport({ ...(data as any), outline: data.outline!, … });
```

教训与本项目反复治的病同形：**「我以为我带全了」**。
挑字段这件事，看起来是在「构造一个干净的对象」，
实际上是在**悄悄决定报告里有什么**。

#### 闸门

新增「the download button never drops a field the renderer needs」：
① 客户端不许再挑字段（源码级）；
② **功能** —— 用同一份报告，有/无 `parameterMatrix` 时主索引行数必须不同
（实测 **317 行 vs 41 行**）。这一条同时把 `extractMasterParams` 导出成可测单元。

**反向测试**：把客户端改回挑字段 → 闸门红。

#### 浏览器里复验

| | 修前 | 修后 |
|---|---|---|
| 弹窗「下载 PDF」 | 4,521,884 字节 · **250 页** | 4,584,894 字节 · **258 页** ✓ |

### 问题 8：顶栏的「Word」按钮把**欢迎语**当报告导出，还报「已下载」

浏览器顺手点了一下顶栏的「Word」（那份文档里「还没测的」就写着它），
结果 **toast 说「WORD 报告已下载」，但下下来的 .doc 只有 2 KB** ——
内容是 chatbot 的那句欢迎语，标题却写着「国标对比 · 法规对比报告」。

根因：导出挑消息只按 `role === "assistant" && m.text`，
而**欢迎语正好满足这两条**（`kind: "welcome"`，role=assistant，有 text）。

**同一份顾虑在单条消息的下载按钮上早就处理了**
（渲染处 `message.kind !== "welcome"`）——
同一个顾虑两处实现，就一定会漂移。

**修**：导出挑消息与按钮禁用判据都加上 `kind !== "welcome"`；
新增闸门把**三处**判据钉在一起（导出挑消息 · 按钮禁用 · 单条消息入口）。

浏览器复验：

| | 修前 | 修后 |
|---|---|---|
| 没有分析结果时点 Word | 导出欢迎语，还报「已下载」 | **按钮禁用**，点了没反应 |
| 有分析结果时点 Word | 导出真答案 ✓ | 导出真答案 ✓（抓请求体确认内容是那条回答） |

## 二之二、第二轮（2026-11-04）：又挖出两个

这一轮是「标题层声明化」改动之后的复测。改动本身是对的，
但**复测**又抓出两个真问题 —— 其中一个让复测本身差点得出错误结论。

### 问题 9：端口被占时**静默换端口** —— 于是浏览器连的是**旧实例**

复测时我从网页拿到的报告，标题还是旧的（「C UN R48 三版本对照」），
而 CLI 重建出来的是新的（「C UN R48-09 三版本对照」）。
第一反应是「代码没生效」，第二反应是「浏览器缓存」——
**两个都是错的**。

真正的原因在服务端的启动逻辑：

```ts
const port = await findAvailablePort(preferredPort);   // 3000 被占 → 3001、3002…
if (port !== preferredPort) {
  console.log(`Port ${preferredPort} is busy, using port ${port} instead`);
}
```

于是：

| 现象 | 后果 |
|---|---|
| 每起一个实例就多一个**活着**的进程，一个都不退出 | 实测一次会话堆到了 **39 个** `tsx server/_core/index.ts` |
| **浏览器里连的 3000 端口，是最早那个旧实例** | 它跑的是旧代码（改源码它不知道），还把报告写回**同一份** `reports/last-report.json` |

最后那条最要命：**「我刚跑出来的报告怎么还是旧的」**，
在服务器日志里查不出任何线索 —— 因为日志在**新起的那个实例**上（在 3001 端口），
而浏览器打的是 3000。

> 这是一个**只有在真实浏览器里才会暴露**的问题：
> 命令行跑 `rebuild_report.mjs` 根本不经过 HTTP，与端口无关。
> 而浏览器这一侧，**「你连的是哪个进程」成了整条链上最脆弱的一环**。

**修**：端口被**本项目的另一个实例**占着时，**响亮地拒绝启动**。
- 每个响应带 `x-regulatory-copilot: <pid>`；
- 启动时探一下目标端口的 `/api/health`，
  读出 PID 认「这是我自己人」→ **拒绝启动**，并打印怎么关掉它；
- 确实是别的程序占了 → 仍可换端口，但**打印得更大声**；
- 逃生开关 `ALLOW_PORT_FALLBACK=1`。

新增闸门「a busy port stops the server instead of silently moving it」
+ 探针的**已知答案**用例 `_test_instance_probe.mjs`（4/4：
带标记认得出、不带标记认不出、没人监听不挂住、非法标记不当 PID）。

**反向测试**：占着 3000 端口再起一个 → 新实例**拒绝启动**并打印关旧进程的命令（已实测）。

### 问题 10：网页面板说「14 章 + **7 附录**」，而报告有 **8 个附录**

面板的附录数取自 `outline.appendices.length`，
而**渲染器与 PDF 目录用的是 `report.appendices`**（8 个）。
两者不一致 —— 目录里有「附H」，面板却说 7 个附录。

根因是历史遗留：`report.appendices` 后来加过附录 H，
`outline.appendices` **没跟着加**。

这一条是「标题层声明化」顺手修掉的：现在两份列表都从
`data/standard-pack.json` 的声明生成，**不可能再对不上**。

## 四、这一轮新增的闸门（117 → 130）

| 闸门 | 守什么 |
|---|---|
| the web UI does not claim a report size it cannot know | 网页文案不手写交付件的页数/章数 |
| the server resolves project paths through one canonical root | 服务端所有路径走同一个项目根解析器 |
| the download filename is derived from the report, not hardcoded | 下载文件名从报告派生，换标准不骗人 |
| the PDF export refuses to serve an unverified draft | 导出端点先判 generator 再渲染；草稿写自己的文件，不覆盖交付件 |
| a draft can never wear the deliverable's name | 草稿的文件名与封面都带「未经回源复核」；没有 generator 标记的也算草稿 |
| the report panel does not call the verified path stream-generated | 面板抬头按管线分支，同一行提到「流式生成」就必须带「未经核验」 |
| no orphan module is left under server/reports | `server/reports/` 下不许留零引用的死代码 |
| the download button never drops a field the renderer needs | 客户端整份带过报告，不挑字段；主索引有/无 `parameterMatrix` 必须行数不同 |
| the welcome message is never exported as if it were an answer | 欢迎语在三处判据里都被排除：导出挑消息 · 按钮禁用 · 单条消息入口 |
| the report names no standard the corpus does not contain | 报告里出现的每个标准号语料里都要有（换标准后那都是假声明） |
| the report's title layer comes from the declaration, not from literals | 封面/章节/附录标题来自 `data/standard-pack.json`；目录与正文必须是同一句 |
| **there is only one report file and one uploaded-docs dir** | 影子路径（`server/reports/last-report.json`、`server/uploaded-docs/`）不许存在 —— 它们一出现就是**两份真相来源** |
| **a busy port stops the server instead of silently moving it** | 端口被本项目的另一个实例占着时**拒绝启动**，而不是悄悄挪到 3001 |

## 五、还没测的

  「a draft can never wear the deliverable's name」钉住）；

  但**两个实例会抢同一份 `reports/last-report.json`** —— 这条已知但没解决。
