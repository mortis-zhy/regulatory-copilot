# 数据文件（**重做**，不是改）

> 这些文件不会被扫 —— 它们**本来就是声明**。
> 但换标准时同样要动：漏掉的后果与漏掉源码一样。

## spec-pack — 参数 spec 包 —— 「这一套标准的每个取值怎么抽」

- **是什么**：第 12 章矩阵的每个取值都来自 `parameter-specs.json` 的一条 spec。**这是本项目最贵的一块内容**（约 800 条正则，每条带 `why`）。
- **换标准时怎么改**：**不要改现有的** —— 另写一套（新标准的 spec 包），否则已交付的 GB 报告再也重跑不出来。人工量由提议层兜着（候选池召回 79.7%），审 593 条候选 + 补那 20%。
- **文件**：
  - `data/parameter-specs.json`
  - `data/parameter-specs-agent.json`
  - `data/parameter-candidates.json`
  - `data/parameter-candidates-c.json`

## derived-data — 派生数据 —— 跑脚本能重出的那些

- **是什么**：这些是从语料与脚本里**推导**出来的（条款索引、附录表范围、覆盖率审计、要求台账）。
- **换标准时怎么改**：换标准后**重跑脚本**重出，不要手工改。改了也不会有人发现 —— 闸门会比对。
- **文件**：

## manual-adjudications — 人工核过的结论 —— 换标准后要**重新核**，不能照搬

- **是什么**：这些是**人逐条看过**的结论：定性义务台账与人工裁定、抽取错误的更正、光色映射、章节对应、缺口的处理方式。
- **换标准时怎么改**：**必须重新核**。照搬会把上一套标准的结论带进新标准 —— 那不是「空着」，是「错着」。人工裁定与机器判定要分开存放（这一条已经是机制）。

## patch-files — 补丁类文件 —— 逐条核对

- **是什么**：逐条的例外名单（条款位图修正、缺口白名单、条款标签修正）。每一条都是**针对某个具体条款**的判断。
- **换标准时怎么改**：逐条对着新标准核。**最容易被漏** —— 因为它们长得像「通用配置」，其实每一条都指向一个具体条款。
- **文件**：
  - `data/clause-bitmap-fixes.json`
  - `data/clause-gap-allowlist.json`
  - `data/clause-label-fixes.json`

## declarations — 标准声明 —— 「这个标准，报告需要知道的一切」

- **是什么**：封面/章节/附录标题的标准名、末版条款号、**各版本的显示名表**（标签/短标签/文档名/标准号/状态/修订号）、**文件名识别签名**（认上传的 PDF 是哪一版）、**客户端的任务简报与界面文案**、**源 PDF 的文件名**。

这一份是**内容里唯一已经声明化**的东西：换标准时改这一个 JSON，代码一行不动。

搬进来的过程（每一处都核过「输出逐字不变」）：
  · `server/reports/versionMeta.ts` 的 12 处字面量 → versions 数组
  · `server/reports/reportV6.ts` 的 40 处版本显示名 → versionLabel/versionDoc/… 调用
  · 六个 Python 脚本的源 PDF 文件名 → scripts/standard_pack.py
  · `python_service/main.py` 的文件名签名与提示 → fileTokens/fileExclude/fileHelp
  · `client/src/pages/Home.tsx` 的任务简报与判据 → clientBrief/clientSetProbe
  · `client/src/components/ReviewWorkbench.tsx` 的版本表头 → versionLabel/versionDoc/versionRev
  · `server/reports/specAgent.ts` 的提示词里的版本代号 → versionLabel/versionDoc
  · `scripts/render_briefing.mjs` / `render_decision_brief.mjs` 的封面标题与文件名 → 声明
- **换标准时怎么改**：改标准族名、末版条款号、版本清单、文件名签名、源文件名、客户端文案；有标准特有的表号（如「表 11.6」）要一并改掉。

**改完跑 `npm run verify`** —— 里面有一关专门验「声明里的标准名语料里真有它」，还有一关验「报告的标题与版本显示名真的来自这份声明」。
