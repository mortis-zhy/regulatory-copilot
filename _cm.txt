fix(ui-pdf): 界面 PDF 按钮改走 V8 管线

问题（用浏览器 MCP 实测发现）:
界面右上角的「PDF」按钮打的是 **/api/agent/report/pdf**，而不是
/api/agent/report/render。该端点使用 export.ts 的旧 renderPdf，把当前对话内容
（794 字节，只有欢迎语）渲染成 PDF。实测结果：
- 修复前：界面下载到的 PDF = **1 页 / 239 字符**（空壳）
- 修复后：**139 页 / 240403 字符**，与 curl 走 V8 结果逐字符相同

修法:
- agentRoutes /api/agent/report/pdf 新增 V8 分支（body.useV8 === true）：读 reports/
  last-report.json → renderPdfFromReportV8 → 139 页。旧分支保留（Word 仍用）。
- Home.tsx 顶部 PDF 按钮改为直接 POST {useV8:true}，不再依赖对话内容。
- Content-Disposition 改 ASCII 文件名：RFC 6266 禁止原生非 ASCII 字节出现在响应头
  （Chromium 拒绝，返回500 Invalid character in header content）。中文显示名由前端 link.download 设定。

验证（Chrome MCP 实测）:
- 点击界面 PDF 按钮 → POST /api/agent/report/pdf 200，content-length 4348029
- 下载文件 C:/Users/zsndz/Downloads/GB4785_多版本横向对比报告.pdf
  → 139 页，文本与 curl 产出 **完全一致**
